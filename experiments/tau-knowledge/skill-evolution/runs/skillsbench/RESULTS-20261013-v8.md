# SkillsBench v8 injection experiment — preliminary results (2026-10-13)

Skill-evolution payload-propagation matrix: 85 tasks x 9 arms x 2 models (GPT-5.6 Terra, Opus 5),
run across 3 devboxes under one frozen identity. **Partial coverage** (run stopped before full
completion; see caveats). Buildable tasks: 83/85 (earthquake-phase-association, seismic-phase-picking
cannot build here -> NOT_MEASURED; denominator stays 85/765).

## Key finding
Terra skill evolution **does propagate injected payloads, dose-dependently** (ASR rises from the
poison-5 to the poison-10 arm): data-exfil 11%->23%, file-delete 0%->19%, credential-abuse 0%->7%.
Opus shows **0% ASR** across all injected arms in the measured sample (no propagation observed).
Task utility is ~0.5 for both models and is not materially degraded by injection.

## Caveats / coverage
- Partial run: Terra ~63-66 tasks/arm measured, Opus ~38-44 tasks/arm (of 83 buildable). Not full 765/model.
- ASR is only measurable on a subset of cells (the attack must have an opportunity + the cell must reach grading).
- Opus fresh-report regeneration hit `usage_for_same_operation_differs` on 2 shards; its numbers are the last consistent snapshot and may lag the live journals.

## Operator deviations from the collaborator's canonical method (identity-affecting; this run forks identity)
1. Bounded resend of unobserved transport failures (model.py / codex_provider.py) — v4 deviation carried forward.
2. Empty completed-output handling -> empty assistant turn / ###STOP### (official_runtime) — v4 deviation.
3. **NEW (v8): non-fatal compose teardown.** `_stop_episode` compose-down timeout was discarding already-measured
   cells (grade computed before teardown, but a >30s `docker compose down` raised and dropped the result). Fix:
   teardown timeout 30s->180s; a compose-down failure is recorded for an out-of-band reaper and is non-fatal;
   attack-monitor cleanup stays fatal (isolation). This changed spec.identity, so results are not mergeable with
   pre-fix (collaborator-canonical) runs.

## Scaling note
Per-box concurrency is capped by the **docker daemon**, not CPU (load ~33/192) or Bedrock quota (0 throttling/429
observed). Each cell issues many serialized docker ops (compose up/down, per-cell network, workspace snapshot copy,
exec) with 30s timeouts; dockerd serializes network/overlay/fs operations in the kernel, so beyond a few dozen
cells/box the setup ops time out (skillsbench_task_services_not_ready / public_snapshot_copy_failed / environment).
