# PDF display-LaTeX extraction

## Scope and prerequisites

This Skill is for **display-mode** math only: formulas occupying their own layout line or block. Never include inline math that shares a prose line. PDF files do not retain their original LaTeX source, so recovered LaTeX is a visual transcription; it must be checked against the rendered PDF rather than assumed correct from text extraction.

At runtime, inspect the supplied PDF (for this task, `/root/latex_paper.pdf`) page by page. Use available local PDF text/layout extraction and page-rendering tools to aid inspection, but treat the rendered page as authoritative. If a tool is unavailable, use another available local inspection method; do not invent formulas from incomplete text output.

## Extraction procedure

1. Render or inspect every page. For two-column pages, inspect each column independently. A formula centered relative to a column is still display math; centering relative to the full page is not required.
2. Select a candidate only when its layout supports it being display math: it is on a separate line/block, has no prose sharing its baseline, and normally has mathematical glyphs and/or surrounding vertical whitespace. Equation numbers at the right margin are not formula content.
3. Transcribe each selected formula into LaTeX that renders like the PDF. Preserve ordering, symbols, grouping, term order, and meaningful spacing/commands. Do not simplify mathematics or replace authorial notation.
4. Compare ambiguous transcriptions with the PDF. Where a renderer is available, render candidate TeX in display math and compare visually. Text extraction/OCR alone is insufficient for subscripts, superscripts, fractions, delimiter size, and column ordering.
5. Supply transcribed candidates to `scripts/package_formulas.py`. It removes outer delimiters, equation tags/numbers, terminal sentence comma/period, and excess whitespace; deduplicates formulas; writes the required artifact.
6. Check each candidate with `scripts/validate_formula.py`. It detects unbalanced `\left`/`\right` pairs and mismatched delimiter types, including `\langle`/`\rangle`, bars, braces, brackets, and parentheses. It reports rather than silently changes a mismatch.
7. Correct only a typo/syntax problem whose intended rendering is clear from the PDF and surrounding notation: e.g. a delimiter mismatch, visibly misspelled standard command, or clearly wrong grouping. Do not fix scientific/physics errors, signs, variables, term order, stylistic forms (`\frac` versus `\dfrac`), or unfamiliar commands that may be paper-defined macros. Retain every original formula and pass each warranted fixed transcription through `corrections`; fixed formulas are appended after all originals.
8. Review the produced Markdown: every nonempty line must be exactly `$$...$$`, with no blank lines and no duplicates. Confirm each original and correction against the PDF/clear contextual evidence.

## Packager interface

Run `scripts/package_formulas.py` with a JSON object on stdin:

```json
{
  "originals": ["\\frac{a}{b}\\quad (1)", "..."],
  "corrections": ["\\frac{a}{b}"],
  "output_path": "/root/latex_formula_extraction.md"
}
```

- `originals` is the ordered list of manually/visually transcribed display formulas. Each string may have outer `$$...$$` or `\[...\]` delimiters.
- `corrections` contains only separately justified corrected versions, in the desired append order.
- `output_path` defaults to `/root/latex_formula_extraction.md` and is where the script writes UTF-8 Markdown.

The script emits JSON containing the cleaned, retained originals/corrections, duplicate/removal warnings, and the output path. It does not identify formulas in a PDF and cannot decide whether an apparent typo is intended; those require visual inspection.

Example executable pipeline after transcription (the JSON may be generated by any local process):

```sh
python3 scripts/package_formulas.py <<'JSON'
{"originals":["\\int_0^x h(t)\\,dt,\\quad (4)"],"corrections":[],"output_path":"/root/latex_formula_extraction.md"}
JSON
```

## Validator interface

Run `scripts/validate_formula.py` with:

```json
{"formula":"\\left\\langle x \\right]"}
```

It emits JSON with `valid_left_right`, `issues`, and non-authoritative delimiter repair suggestions. A suggestion is not evidence to edit a formula: choose the repaired version only after visual/contextual confirmation, then submit it as a correction to the packager.

The packager rejects non-string input and formulas with unresolved newline characters after normalization. If no display formulas exist, it writes an empty file. If a formula cannot be faithfully transcribed or a proposed correction cannot be justified, report/retain only what can be evidenced rather than making an unsupported correction.
